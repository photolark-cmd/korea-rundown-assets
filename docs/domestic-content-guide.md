# 국내용 블로그 콘텐츠 가이드

> **플랫폼: 네이버 블로그.** 영문 `korearundown.blogspot.com`(Blogger)과는 검색 생태계가
> 다르므로 글쓰기 방식도 다릅니다. 네이버 특유의 운영 지침은 [§10](#10-네이버-블로그-운영-지침)에 모아 뒀습니다.

## 이 문서가 있는 이유

유튜브 영상 대본을 블로그 소스로 쓰면, **블로그 발행량의 상한이 영상 제작 속도에 묶입니다.**
영상을 한 달에 2편 만들면 블로그도 사실상 거기서 멈춥니다.

소스를 영상 대본에서 **1차 데이터**로 옮기면 그 상한이 사라집니다. 통계는 매달 갱신되고,
보도자료는 매주 나오고, 공시는 분기마다 쌓입니다. 이 문서는 그 전환을 위한 작업 지침입니다.

---

## 원칙 4가지

1. **대본이 아니라 데이터에서 출발한다.** 영상은 소재의 한 갈래일 뿐, 유일한 입구가 아니다.
2. **글 1편 = 숫자 1개.** 썸네일 템플릿(`_template.html`)이 이미 이 포맷을 강제하고 있다.
   숫자 하나가 안 잡히면 아직 글이 될 준비가 안 된 소재다.
3. **매 글마다 직접 만든 표나 계산을 최소 1개 넣는다.** 이게 품질 하한선이자 복제 콘텐츠
   방어선이다. 양산해도 이 조건만 지키면 문제되지 않는다.
4. **국내용은 감탄이 아니라 검색 의도에 답한다.** 영어권 독자용이 "한국이 왜 편한가"라면,
   국내 독자는 "얼마인가 / 어디서 하나 / 어떻게 신청하나"를 검색한다.
   같은 소재라도 영문판을 번역하지 말고 재구성한다.

## 2. 숫자 하나에서 글 여러 편 뽑기

숫자 하나를 잡았으면 아래 5개 각도로 돌립니다. 각 각도가 독립된 검색 의도라
카니벌라이제이션(자기 잠식) 없이 5편이 나옵니다.

| 각도 | 질문 | 제목 틀 |
|---|---|---|
| 사실 | 지금 얼마인가 | `2026년 OOO 요금 총정리` |
| 이유 | 왜 그 값인가 | `OOO 요금은 어떻게 정해지나` |
| 비교 | 다른 데는 어떤가 | `서울 vs 도쿄 OOO 비교` |
| 추이 | 어떻게 변해왔나 | `OOO 10년 추이와 다음 인상 시점` |
| 실전 | 그래서 뭘 하면 되나 | `OOO 아끼는 방법 / 신청 절차` |

**예시 — "지하철 기본요금" 하나로:**
현재 요금 정리 / 거리비례제 계산 구조 / 해외 도시 비교 / 인상 이력과 추이 /
환승 할인 최대로 받는 법 → 5편.

## 3. 검색 의도별 글 유형

국내 유입은 대부분 롱테일 쿼리입니다. 기획 단계에서 의도를 먼저 정합니다.

| 의도 | 쿼리 예 | 글 형식 | 핵심 요소 |
|---|---|---|---|
| 금액 확인 | `OOO 요금 얼마` | 표 중심 단문 | 최신 금액 표, 갱신일 명시 |
| 절차 | `OOO 신청 방법` | 단계별 | 스크린샷/체크리스트, 준비물 |
| 비교 | `A vs B` | 비교표 | 항목별 표 + 결론 한 줄 |
| 변화 | `OOO 인상 언제` | 뉴스형 | 근거 보도자료 링크, 시행일 |
| 배경 | `OOO 왜 싼가` | 설명형 | 구조 설명 + 데이터 |

**갱신일을 본문 상단에 쓰세요.** 금액 글은 이게 신뢰도와 재방문을 좌우합니다.

### 키워드는 어디서 찾나 (네이버 기준)

| 도구 | 얻는 것 | 비고 |
|---|---|---|
| 네이버 검색광고 키워드도구 `searchad.naver.com` | **월간 검색수 실측**(PC/모바일 분리) | 광고 계정 필요(무료). 국내 키워드 물량의 사실상 유일한 실측치 |
| 검색창 자동완성 | 사람들이 실제로 치는 어순 | 제목에 그 어순 그대로 쓰기 |
| 검색결과 하단 연관검색어 | 파생 소재 | 그대로 다음 글 주제가 됨 |
| 네이버 데이터랩 `datalab.naver.com` | 검색어 추이(계절성) | 상대 지수라 절대 검색량은 아님 |
| 지식iN · 카페 질문 | 문장형 롱테일 | FAQ 섹션 재료 |

순서: 키워드도구에서 **검색수는 있는데 문서수는 적은** 키워드를 찾고 → 자동완성으로 어순 확정 →
연관검색어로 다음 편 예약. 이게 §2의 "숫자 하나 → 5편"과 맞물립니다.

## 5. 유튜브 영상 → 글로 분해

기존 영상을 버릴 필요는 없습니다. 다만 **통으로 옮기지 말고 쪼갭니다.**
영상 1편 → 보통 4~6편:

| # | 글 | 성격 |
|---|---|---|
| 1 | 사전 리서치 글 | 영상 만들며 조사한 것 중 안 쓴 데이터 |
| 2 | 본편 요약 + 영상 링크 | 영상 유입용. 단 §10 참고 — 네이버에서 유튜브 임베드는 검색상 이점이 없음 |
| 3~4 | 곁가지 소재 | 영상에서 30초로 지나간 것을 한 편으로 |
| 5 | 댓글 FAQ | 실제 질문 = 실제 검색어 |
| 6 | 데이터 업데이트 | 수치 갱신 시점에 재발행 |

단, 이건 **배수를 늘려줄 뿐 상한 자체는 그대로**입니다. 주축은 1번 항목(데이터 기반)이어야 합니다.

## 6. 발행 전 체크리스트

- [ ] 제목에 검색될 쿼리가 들어갔는가
- [ ] 핵심 숫자 1개가 명확한가

- [ ] 모든 수치에 출처와 기준 시점이 붙었는가
- [ ] 갱신일을 상단에 적었는가
- [ ] 남의 문장을 그대로 옮긴 곳이 없는가
- [ ] 썸네일이 `thumbnails.kr.csv`에 등록됐는가
- [ ] 표를 **스마트에디터 표**로 넣었는가 (캡처 이미지로 넣으면 검색에 안 잡힘)
- [ ] 대표이미지를 지정했고, 목록에서 잘리지 않는가 (§8)
- [ ] 태그를 주제 축에 맞게 달았는가 (§10 — 주제를 흩뜨리지 않기)

## 7. 저작권 안전선

| 대상 | 되는 것 | 안 되는 것 |
|---|---|---|
| 내 유튜브 영상 | 전부 자유 (대본 재구성, 캡처, 자막) | — |
| 타 채널 영상 | 짧은 요약 + 출처 링크 + 공식 임베드 | 대본 받아쓰기, 영상 재업로드 |
| 통계·보도자료 | 수치 인용, 표를 직접 재구성 | 표 이미지 그대로 퍼가기 |
| 기사 | 사실 인용 + 출처 링크 | 문장·문단 복제, 기사 사진 사용 |
| 공공 이미지 | 공공누리 유형 확인 후 표기 | 유형 확인 없이 사용 |

원칙: **사실과 수치는 자유롭게, 표현은 직접.** 표를 직접 재구성하는 습관이
저작권과 콘텐츠 품질을 동시에 해결합니다.

## 8. 썸네일까지 한 번에

글을 기획하면 썸네일 행을 바로 추가합니다. 원고와 이미지가 따로 밀리지 않게.

국내용과 영문용은 **프로파일로 분리돼 있습니다.** 국내용은 `thumbnails.kr.csv`에만
쓰면 되고, 시리즈명·브랜드·블로그 주소는 프로파일 기본값이 자동으로 붙습니다.

```csv
slug,part,figure,unit,kicker
subway-fare-2026,,OOO원,기본요금,OOkm까지 **동일 요금**입니다.|이후 OOkm마다 OO원씩 붙고요.
```

(숫자는 자리표시자입니다. 실제 값은 §1의 소스에서 확인하고 채우세요.)

```bash
node tools/render-thumbnails.mjs --profile kr --skip-existing
```

`kr/` 폴더에 **1080×1080 정사각**으로 렌더됩니다. `--skip-existing`은 기존 PNG를
건드리지 않고 새 행만 그립니다. 자세한 사용법은 [`tools/README.md`](../tools/README.md).

### 왜 정사각인가

영문용(1200×630)은 구글·SNS 미리보기(OG) 규격입니다. 그런데 이 디자인은 숫자·카피·브랜드가
전부 왼쪽 정렬이라 **가운데 정사각으로 자르면 숫자가 중간에서 잘리고 브랜드와 블로그 주소가
통째로 사라집니다.** 실제로 잘라서 확인한 결과입니다.

그래서 국내용은 처음부터 정사각으로 렌더합니다. 잘릴 걱정 없이 목록·검색·본문 어디에 쓰든
전체가 보입니다.

> 🔍 **한 번만 확인해 주세요.** 네이버가 실제로 어느 화면에서 어떤 비율로 자르는지는
> 한 편 올려보는 게 가장 빠릅니다. 1080×1080이 과하거나 다른 비율이 낫다면
> `tools/profiles.json`의 `kr.width` / `kr.height`만 고치면 됩니다.

### 처음 한 번 할 일

`tools/profiles.json`의 `kr.defaults.sub`가 자리표시자(`blog.naver.com/아이디`)입니다.
실제 블로그 주소로 바꿔 주세요. 한 번 고치면 이후 모든 썸네일에 적용됩니다.

## 10. 네이버 블로그 운영 지침

국내용은 **네이버 블로그**입니다. 영문 Blogger와는 검색 생태계가 아예 다르므로
글쓰기 방식도 달라집니다.

### 검색 노출 로직

네이버가 공개한 랭킹 요소는 크게 둘입니다.

- **C-Rank** — *출처(블로그)* 가 특정 주제에서 얼마나 신뢰할 만한가
- **D.I.A / D.I.A+** — *문서 하나* 가 얼마나 좋고 질의 의도에 맞는가

여기서 나오는 실무 결론 하나가 중요합니다:

> **주제를 흩뜨리지 마세요.** C-Rank는 주제별로 쌓입니다. 생활·경제 정보로 100편을 쌓은
> 블로그와, 맛집·여행·정보가 섞인 블로그 100편은 같은 100편이 아닙니다.
> 카테고리를 고정하고 그 안에서만 발행하는 편이 유리합니다.

Korea Rundown 소재(편의점·배달·교통·의료·요금)는 **"생활 속 비용·제도"** 라는 한 주제로
묶입니다. 이 축을 벗어나지 않는 게 좋습니다.

### 속설과 사실을 구분하세요

국내 블로그 커뮤니티에는 "블로그 지수", "저품질", "글자수 1500자 이상", "이미지 10장",
"외부링크 금지" 같은 말이 돌지만 **네이버가 공식 확인한 기준이 아닙니다.**
수치 규칙을 맹신하지 말고, 공식적으로 확인된 방향(주제 전문성 + 문서 품질 + 의도 부합)에
맞추는 편이 안전합니다. §6 체크리스트가 이미 그 방향입니다.

### 수익화 — 애드센스가 아니라 애드포스트

네이버 블로그는 임의의 HTML/JS를 넣을 수 없어 **구글 애드센스를 달 수 없습니다.**
수익 수단은 네이버 **애드포스트**이고, 단가는 애드센스보다 낮습니다.

그래서 국내용 블로그는 **광고 수익 자체를 목표로 잡으면 실망하기 쉽습니다.**
현실적인 목표는 이쪽입니다:

- 검색 유입 → 브랜드 인지 → 유튜브·영문 블로그로 연결
- 협업·제휴·체험단 제안이 들어오는 창구

### 유튜브와의 관계

네이버 블로그에 유튜브 영상을 넣어도 **검색 노출에는 이점이 없습니다.**
네이버는 자사 영상을 우대하고, 유튜브 임베드는 그냥 본문 요소일 뿐입니다.

즉 **국내용 블로그를 유튜브에 묶을 이유가 더 줄어듭니다.**
유튜브 링크는 이미 들어온 독자를 채널로 보내는 *유입 장치*로만 쓰고,
글의 소재와 순서는 §1의 데이터와 §3의 검색량이 정하게 하세요.

### 영문 블로그와의 관계

네이버 블로그는 구글 색인에 약하고, Blogger는 네이버 색인에 약합니다.
사실상 겹치지 않으므로 **중복 콘텐츠 걱정은 크지 않습니다.**
다만 같은 글을 그대로 양쪽에 올리는 건 피하세요 — 독자층의 검색 의도가 다르기 때문에
(§원칙 4) 어차피 그대로 옮기면 양쪽 다 안 먹힙니다.
