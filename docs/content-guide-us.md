# 영문 블로그 콘텐츠 가이드

> **플랫폼: Blogger (`korearundown.blogspot.com`).** 국내용([`content-guide-kr.md`](content-guide-kr.md))과는
> 조건이 상당 부분 **반대**입니다. 번역해서 쓰면 양쪽 다 실패합니다.
> 뉴스를 소재로 빠르게 발행할 때는 [`newsjacking-playbook.md`](newsjacking-playbook.md).

## 국내용과 무엇이 다른가

| | 국내 (네이버) | 영문 (Blogger) |
|---|---|---|
| 검색엔진 | 네이버 | 구글 |
| 수익화 | 애드포스트만 (애드센스 불가) | **애드센스 가능** + 제휴 |
| 유튜브 임베드 | 검색상 이점 없음 | **이점 있음 — 상호 유입 작동** |
| 독자 의도 | 거래형 (얼마·어디서·어떻게) | 조사형 (여행 전 · 이주 전 · 비교 호기심) |
| HTML 제어 | 불가 | 전면 가능 (메타태그·구조화 데이터) |
| 썸네일 | 1080×1080 정사각 (`kr`) | 1200×630 OG (`us`) |
| 외부 확산 | 거의 없음 | Reddit·SNS 공유로 유입 발생 |

가장 큰 차이 둘만 기억하면 됩니다. **영문에서는 애드센스가 되고, 유튜브 연계가 실제로 작동합니다.**

---

## 원칙 4가지

1. **비교가 상품이다.** "한국에 편의점이 많다"는 어디서나 읽을 수 있습니다.
   값이 나가는 건 **환산되고 비교 가능해진 숫자**입니다 — `1 : 950` vs `1 : 2,257`처럼.
   기존 썸네일 4장이 전부 이 구조인 건 우연이 아닙니다.
2. **숫자는 독자의 단위로 환산해서 준다.** 원화만 적으면 독자가 계산기를 켜야 하고,
   대부분은 그냥 이탈합니다. 달러 병기 + 환율 기준일은 필수입니다.
3. **1차 경험을 드러낸다.** 구글이 공개한 평가 가이드라인은 직접 경험을 명시적으로 강조합니다.
   "여기 살면서 실제로 겪은 것"은 AI가 긁어모은 글이 못 가지는 자산입니다. 숨기지 말고 쓰세요.
4. **유튜브를 버리지 않는다.** 국내용과 정반대입니다. 아래 §8 참고.

## 1. 독자와 검색 의도

영문 독자는 한국에 **아직 안 온 사람**이거나 **막 온 사람**입니다. 국내 독자처럼
"오늘 얼마 내야 하나"가 아니라 "가기 전에 알아둘 것"을 찾습니다.

| 독자 | 쿼리 패턴 | 원하는 것 |
|---|---|---|
| 여행 예정자 | `how much is food delivery in Korea` | 예산 감각, 준비물 |
| 이주·주재 예정자 | `healthcare in Korea for foreigners` | 절차, 실제 비용 |
| 비교 호기심 | `why is Korea so convenient` | 구조적 이유, 미국과의 차이 |
| 유학생 | `living cost Seoul vs New York` | 항목별 비교표 |

제목 틀:

- `How Much Does X Cost in Korea? (2026 Guide)`
- `X in Korea vs the US: What Actually Differs`
- `Why Korea's X Works the Way It Does`
- `A Foreigner's Guide to X in Korea`

**연도를 제목에 넣으세요.** 조사형 쿼리는 최신성이 클릭을 좌우합니다.

## 2. 소스

> ⚠️ 아래 링크는 이 문서를 쓴 환경에서 네트워크 정책상 접속 검증을 하지 못했습니다.
> 처음 쓸 때 확인하고, 바뀐 주소는 이 표를 고쳐 주세요.

### 한국 측

국내 가이드 [§1](content-guide-kr.md)과 동일합니다 — KOSIS, 공공데이터포털, 부처 보도자료, DART.
**같은 데이터를 두 블로그가 함께 씁니다.** 한 번 조사하면 양쪽 글이 나오는 구조라,
발행량을 늘릴 때 이게 가장 큰 지렛대입니다.

### 미국 측 (비교값)

| 소스 | 얻는 것 |
|---|---|
| BLS `bls.gov` | 소비자물가, 품목별 평균 가격 |
| FRED `fred.stlouisfed.org` | 경제 시계열, 환율 |
| U.S. Census `census.gov` | 인구·사업체 수 (비율 계산의 분모) |
| KFF `kff.org` | 의료비·보험 통계 |
| NACS `nacsonline.com` | 미국 편의점 점포 수 |
| 각 교통국 공식 요금표 (MTA 등) | 대중교통 요금 |

### 피해야 할 것

**Numbeo 같은 크라우드소싱 물가 사이트를 1차 근거로 쓰지 마세요.** 이용자 입력 기반이라
표본이 들쭉날쭉하고, 반박당하기 쉽습니다. 영문 독자층은 출처를 따지는 경향이 강합니다.
정 쓰겠다면 "crowd-sourced estimate"라고 성격을 밝히고 보조로만.

## 3. 환산 규칙

비교 글의 신뢰도는 여기서 갈립니다.

- **환율과 기준일을 반드시 명시.** `₩2,500 (about $1.80 at ₩1,390/USD, Feb 2026)`
- **원화를 지우지 말 것.** 한국에 오는 독자는 현지에서 원화를 봅니다
- **반올림은 읽기 좋게, 원본은 정확하게.** 본문은 `about $1.80`, 표는 `$1.79`
- **단위 병기** — `10 km (6.2 miles)`
- 큰 금액은 **연 단위 환산**을 덧붙이면 체감이 살아납니다

한 글 안에서는 **환율 하나로 고정**하고 그 값을 상단에 적으세요. 문단마다 다른 환율을
쓰면 표가 서로 안 맞습니다.

## 4. 표현 규칙

- **로마자 표기 일관성** — 한 글에서 `Myeongdong` / `Myeong-dong`을 섞지 않기
- **한국어 용어는 첫 등장 시 설명** — `jeonse (a lump-sum deposit lease)`. 두 번째부터는 그냥 씀
- **날짜는 풀어서** — `March 3, 2026` (`3/3` 는 국가마다 해석이 다름)
- **"we/us"가 누구인지 분명히** — 독자는 미국인, 필자는 한국 거주자. 이 위치를 흐리지 말 것
- **과장 금지** — `the best in the world` 류는 신뢰를 깎습니다. 숫자가 대신 말하게

## 5. 시각 자료 — 글이 숫자만 있으면 안 읽힙니다

### 직접 만든 이미지는 적극 권장입니다

위험한 건 **남의 사진**이지 자기 이미지가 아닙니다. 자체 제작 이미지는 세 가지를 한 번에 해결합니다 —
저작권 리스크 0, 브랜드 일관성, 그리고 §원칙 3의 1차 경험 신호.

### 무엇을 넣을까 (효과 순)

**1. 직접 찍은 사진 — 가장 강력합니다**

편의점 매대, 지하철 개찰구와 요금표, 배달 영수증, 병원 수납 영수증, 자판기, 무인점포.
AI가 만들 수 없고 경쟁자가 가질 수 없는 유일한 자산입니다. 영문 독자가 "이 사람 진짜 거기 산다"고
믿게 만드는 것도 이겁니다.

- 개인정보(카드번호·이름·주소·전화번호)는 반드시 가리기
- **평소에 찍어 쌓아두세요.** 글 쓸 때 찍으러 나가면 발행이 하루 밀립니다

**2. 비교 차트** — 본문 비교표와 같은 데이터를 시각적으로 한 번 더

**3. 숫자 카드** — 썸네일과 같은 형식을 본문 중간에. 긴 글의 호흡을 끊어줍니다

**4. 설명 다이어그램** — 거리비례 요금 구조처럼 말로 하면 길어지는 것

### 쓰면 안 되는 것

- **언론사 사진** — 국내 통신사·신문사는 무단 사용에 실제로 적극 대응합니다
- 구글 이미지 검색에서 가져온 것 (출처 불명 = 확인 불가 = 위험)
- 라이선스 확인 안 한 스톡 이미지

### 안전한 외부 소스

- **공공누리** — 유형(1~4) 확인하고 표기하면 사용 가능
- Unsplash·Pexels 등 — 라이선스는 안전하지만 **한국 현장감이 약합니다.**
  일반적인 도시 사진은 오히려 신뢰를 깎으니 보조로만

### 배치 규칙

- 스크롤 **2~3화면마다 1장**
- **alt 텍스트 필수** — 검색 노출과 접근성 양쪽에 걸립니다
- 파일명도 검색어로 — `seoul-subway-fare-2026.png`
- **표를 이미지로 만들지 마세요.** 이미지 속 숫자는 색인되지 않습니다.
  표는 HTML 텍스트, 차트는 이미지 — 둘은 역할이 다릅니다

### 브랜드 일관성

썸네일 팔레트를 본문 이미지에도 쓰면 낱개 글이 아니라 시리즈로 읽힙니다.
값은 [`_template.html`](../_template.html)에 정의돼 있습니다.

| 용도 | 값 |
|---|---|
| 배경 | `#0E2A33` → `#113B47` (그라디언트) |
| 강조 (골드) | `#D9A441` · `#F3C063` |
| 보조 (하늘) | `#9FD3E0` · `#7FC3D4` |
| 본문 텍스트 | `#F4F1EA` |

비교 차트·추이 차트·숫자 카드는 **CSV에서 바로 뽑을 수 있습니다.**

```bash
node tools/render-figures.mjs
```

`figures.csv` 한 줄이 이미지 한 장입니다. 색과 배치는 이미 브랜드 팔레트로 맞춰져 있고,
밝은 배경/어두운 배경 둘 다 지원합니다. 사용법은 [`tools/README.md`](../tools/README.md).

## 7. 구글 검색 대응

Blogger는 HTML을 만질 수 있으니 국내용에서 못 하던 걸 할 수 있습니다.

- **`og:image`** — `us` 프로파일 썸네일이 이미 1200×630 OG 규격입니다. 템플릿에 연결만 하면 됩니다
- **`<title>` / meta description** — 포스트마다 개별 지정
- **사이트맵을 Search Console에 제출**하고 색인 상태를 주기적으로 확인
- **내부 링크로 시리즈를 묶기** — Part 1~4가 서로를 가리키게. 체류시간과 색인 모두에 유리
- **구조화 데이터**는 `Article` 수준으로 충분합니다.
  FAQ 리치결과는 대부분의 사이트에서 노출이 축소됐으니 그걸 노리고 넣지는 마세요
- **커스텀 도메인**을 붙이면 장기적으로 유리합니다 (`blogspot.com` 서브도메인보다)

## 8. 유튜브 연계 — 국내용과 정반대

네이버에서는 유튜브 임베드가 검색상 아무 이점이 없었습니다. **구글에서는 다릅니다.**

- 영상 임베드가 블로그 체류시간을 늘리고, 블로그가 영상 시청시간을 늘립니다 (양방향)
- 유튜브 영상 자체가 구글 검색결과에 노출될 수 있습니다
- 영상 설명란 → 블로그 링크가 실제 유입으로 이어집니다

**그래서 영문 블로그는 유튜브와 묶어 두는 게 맞습니다.**
다만 여전히 **소재의 유일한 입구로 삼지는 마세요.** 발행량이 영상 제작 속도에 묶이는
문제는 플랫폼과 무관합니다. 영상은 있으면 얹고, 없으면 데이터로 씁니다.

영상 1편 → 글 4~6편 분해는 국내용 [§5](content-guide-kr.md)와 동일하되,
여기서는 **임베드가 실제로 값을 하므로** 본편 요약 글의 우선순위가 더 높습니다.

## 9. 수익화

국내용과 가장 크게 갈리는 지점입니다.

- **애드센스** — Blogger에 기본 통합돼 있습니다. 국내(네이버)에서는 불가능했던 선택지
- **제휴** — 영문 독자층은 여행 전 조사 단계라 실제로 맞는 상품이 있습니다
  (eSIM/유심, 교통패스, 숙박, 여행보험). **제휴 링크는 반드시 명시**하세요.
  숨긴 제휴 링크는 신뢰와 정책 양쪽에서 손해입니다
- 수익 규모만 보면 영문 쪽이 국내용보다 현실성이 큽니다. 발행 우선순위를 정할 때 감안하세요

## 10. 확산 (국내용에 없는 채널)

네이버 블로그와 달리 영문 글은 **검색 외 유입이 실제로 발생합니다.**

- Reddit (`r/korea`, `r/travel` 등) — 단, 자기 링크만 던지면 역효과입니다.
  질문에 본문으로 답하고 근거로 링크하는 방식으로
- 커뮤니티 답변에서 자기 표를 인용 → 자연 유입
- 다만 **이건 스파이크성 유입**입니다. 기반은 검색이어야 합니다

## 11. 발행 전 체크리스트

- [ ] 제목에 타깃 쿼리와 연도가 들어갔는가
- [ ] **한국 숫자와 미국 숫자가 같은 표에 있는가** ← 영문판의 핵심
- [ ] 모든 금액에 달러 환산과 환율 기준일이 붙었는가
- [ ] 한 글 안에서 환율이 하나로 통일됐는가
- [ ] 직접 만든 표나 계산이 1개 이상 있는가
- [ ] 로마자 표기가 일관되는가
- [ ] 한국어 용어를 첫 등장 시 설명했는가
- [ ] 1차 경험이 드러나는 문장이 있는가
- [ ] 이미지가 최소 2장 있고, 전부 직접 제작하거나 라이선스를 확인했는가 (§5)
- [ ] 모든 이미지에 alt 텍스트를 넣었는가
- [ ] 표를 이미지가 아니라 텍스트로 넣었는가
- [ ] `og:image`와 meta description을 지정했는가
- [ ] 시리즈 내부 링크를 걸었는가
- [ ] 제휴 링크가 있다면 명시했는가
- [ ] 썸네일을 `thumbnails.us.csv`에 등록하고 렌더했는가

## 12. 썸네일

```bash
node tools/render-thumbnails.mjs --profile us --skip-existing
```

`thumbnails.us.csv`에 행을 추가하면 저장소 루트에 1200×630 PNG가 생깁니다.
시리즈명·브랜드·블로그 주소는 `us` 프로파일 기본값이 자동으로 붙습니다.

```csv
slug,part,figure,unit,kicker
part5-wifi,Part 5,$0,for public Wi-Fi,Seoul runs it as **infrastructure**.|Most US cities leave it to cafés.
```

`**강조**`는 골드, `|`는 줄바꿈. 자세한 사용법은 [`tools/README.md`](../tools/README.md).

**숫자는 비교 가능한 형태로 넣으세요.** 썸네일이 이미 "한국 값 하나"를 강제하는 포맷이라,
본문의 비교 대상까지 kicker에 넣으면 클릭 이유가 명확해집니다
(`The U.S. ratio is 1 : 2,257` 처럼).

## 13. 발행 리듬 (예시)

주 2편 기준. 국내용과 **같은 조사에서 나옵니다.**

- **1편** 데이터 비교 신작 — 한국 숫자 + 미국 숫자
- **1편** 영상 분해분 또는 기존 글 갱신 (환율·요금이 바뀌면 재발행)

같은 소재를 국내용과 영문용으로 각각 재구성하면 조사 1회에 글 2편이 나옵니다.
**번역이 아니라 재구성입니다** — 독자의 검색 의도가 다르기 때문에 그대로 옮기면 양쪽 다 안 먹힙니다.
