- **확대** — 드래그한 영역으로, 원본·결과가 **같은 배율 같은 자리**. 배율 표시됨
- **점 / 영역 / 자유** 표시 — 화면에서 짚으면 그 표시를 그림에 그려 Claude에게 보낸다
- **얼굴 부위별 게이지** 17개 (누적 안 됨 — 조정 시작 시점 이미지에서 매번 다시 만든다)

### 학사모 전용
- `guide_check` — 형님 가이드라인(빨간 선)을 그대로 측정. 형님 보정본이 이 축들로
  수렴하는 것을 확인했다 (모자 +6.3°→+0.1°, 중심 +18.1%→+1.2%, 고개 +3.1°→+0.1°)
- `crop_print` — 10:13 인화 크롭. 위는 모자 높이만큼 여백, 아래는 사진 끝까지
  (배경지가 남아도 템플릿에서 다시 잘린다)
- `add_tassel` — 술 합성. **판의 꼭짓점**에 매달고 **수직으로** 떨어뜨린다.
  길이는 꼭짓점~입선이라 머리 크기에 비례한다. **블러본만 쓴다**(선명본은 아이
  얼굴보다 술이 튄다). 소재는 `assets/tassels/current.json`이 가리킨다.
- `face_size` — 얼굴 균일 축소. 형님은 중간값 0.65%, 최대 5%까지 줄인다(실측).

## 이 세션에서 크게 틀린 것 (반복하지 말 것)

1. **저장소에 있으니 형님 작업물이라고 가정했다.** 두 번 지적받았다.
   EXIF 바디 시리얼로 확인할 수 있었는데 안 했다.
2. **파일명만으로 원본/보정본을 짝지었다.** 번호가 의상 세트마다 1부터 다시
   시작해서 같은 아이의 **다른 옷 사진**끼리 묶였다. 변형량이 얼굴 폭의 55%로
   나왔는데 "전신 정렬 때문일 것"이라고 그럴듯하게 넘어갈 뻔했다.
   **여섯 쌍을 나란히 띄워 보니 1초 만에 드러났다.**
3. **크기가 다르다고 955쌍을 버렸다.** 실제로는 EXIF 회전 표기 차이였고,
   진짜 잘린 것도 얼굴 기준 정렬로 쓸 수 있었다.
4. **`cv2.imwrite`가 한글 경로에서 조용히 실패하는데 반환값을 안 봤다.**
   "319쌍 준비 완료"라고 보고하면서 파일은 한 장도 없었다. 두 단계 뒤에 드러났다.
5. **지표만 보고 학습 성공이라고 할 뻔했다.** 오차는 21% 좋아졌는데 그림은
   눈썹까지 뭉개져 못 쓸 상태였다. **숫자가 좋아져도 눈으로 본다.**
6. **2018년 술 소재를 현행이라고 가정했다.** 파일명에 연도가 적혀 있었는데 안 봤다.

공통점: **확인할 수 있는 것을 확인 안 하고 가정했다.** 사진은 띄워 보면 되고,
EXIF는 읽으면 되고, 파일은 세어 보면 된다.

## 이전 세션 (2026-09-09, 클라우드)

- `photo-fix`(색) → 인물 일괄(학습) → 스튜디오(대화창) → 포토샵 도구 → 학사모 전용 순으로 확장
- 만화 얼굴 합성 데이터는 배관 검증에만. 랜드마크가 흔들려 수치 비교가 안 된다
- 모자 판 자리 채우기는 단순 인페인팅이면 몸통 색이 번진다 → 배경 추정색 + 몸통 겹침만 벨벳
- 정규화 블러 외삽은 분모가 0에 가까우면 검게 무너진다 → 넓은 시그마로 단계적 대체
- OpenCV xphoto 패치 인페인팅은 인물·의자 조각을 배경에 복사한다 → 미채택

### 아직 남은 약점
1. `extend_backdrop`은 채울 곳을 자동으로 못 찾는다 → 이제 화면에서 **자유선으로 그려** 줄 수 있다
2. 모자 각도 측정 오차 ±0.8°, 한 번만 회전한다(반복하면 발산)
3. 얼굴 리퀴파이는 큰 값(>30) 미확인
4. 이 보이는 웃음·감은 눈 뜨기는 생성 없이 안 됨 → 같은 촬영 다른 컷에서 이식만 가능
